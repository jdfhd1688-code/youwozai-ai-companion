# 有我在产品需求文档

## 文档目的

定义“有我在”MVP 要验证的用户问题、产品边界和验收标准。当前结论是产品已具备可演示闭环，但用户需求强度和持续使用意愿仍需真实验证。

## 问题定义

用户情绪波动时，传统日记的启动成本较高；普通 AI 聊天又容易在对话结束后失去长期价值。项目希望验证：自然陪伴式对话能否降低记录门槛，并在用户拥有最终控制权的前提下沉淀可回顾数据、连接可信支持。

## 目标用户与使用场景

### 核心用户

- 18 岁以上、具备基本数字产品使用能力。
- 偶尔或持续有情绪记录需求。
- 不希望一开始进入医疗化、诊断式体验。
- 关注隐私，愿意自行决定是否建立守护圈。

### 核心任务

- 当我说不清自己的感受时，希望有人先接住我的表达。
- 当一次聊天有记录价值时，希望快速整理并由我确认。
- 当我回顾最近状态时，希望看到趋势而不是零散对话。
- 当我处于高风险状态时，希望获得清晰、克制、可控的现实支持入口。

## 产品原则

1. 陪伴先于分析，不诊断、不评判。
2. 用户确认先于数据沉淀。
3. 明确授权先于信息分享。
4. 确定性安全流程优先于生成式表达。
5. AI 能力失败时保留核心功能。

## MVP 范围

### 必须实现

- 注册、登录、退出与注销。
- 陪伴对话和低、中、高风险路由。
- 情绪结构化草稿、编辑、确认、保存和删除。
- 历史记录、趋势与每周来信。
- 守护人管理和逐项授权。
- High Risk 安全行动、通知确认、撤销和审计。
- AI 记忆的查看和管理。
- 自然 TTS 主链路、系统语音降级、自动播放设置和单音轨播放。

### 明确不做

- 医学诊断、治疗建议和临床量表结论。
- 自动报警或绕过用户确认联系第三方。
- 真实短信、微信、电话或 Push 通知。
- 实时语音通话、视频通话和社区功能。
- 未成年人专门服务。

## 核心用户流程

### 普通情绪记录

1. 用户输入一段经历或感受。
2. 小在回复，系统给出结构化草稿。
3. 用户修改或确认草稿。
4. 系统写入情绪记录。
5. 记录参与趋势和每周来信聚合。

### 高风险流程

1. 输入命中高风险信号。
2. 系统立即进入固定安全流程，不等待外部模型决定。
3. 页面呈现短句安抚和三个主操作。
4. 若用户选择联系守护人，先检查事先授权。
5. 生成待确认通知，用户可发送或撤销。
6. 系统保存通知状态和审计记录。

## 功能验收标准

| 能力 | 验收标准 |
| --- | --- |
| 登录 | 错误凭证不创建会话，登录后只能读取本人数据 |
| 聊天 | 外部 LLM 不可用时仍返回本地陪伴文本和结构化草稿 |
| 风险 | 高风险关键词与上下文规则能触发固定 Safety Workflow |
| 记录 | 未经确认不保存；保存后可查看、修改和删除 |
| 守护圈 | 每位守护人的权限独立，未授权字段不进入通知内容 |
| 语音 | 首次操作解锁；开启自动播放后同 session 自动播放；任何时刻只有一条语音 |
| 降级 | LLM 或 TTS 失败不影响文字主流程 |
| 切页 | 离开当前页面时停止正在播放和等待中的音频 |

## 成功指标

以下为待验证目标，不是现有成果：

- 首次任务中，至少 70% 用户能在无帮助情况下完成一条情绪记录。
- 至少 70% 用户能正确解释“守护圈不会自动发送未经授权的信息”。
- High Risk 场景中，至少 80% 用户能在 10 秒内找到现实求助入口。
- 试用结束后，至少 50% 用户表达未来七天再次使用意愿。
- TTS 开启用户中，语音成功启动率达到 95% 以上。

## 主要风险

- 用户把陪伴误解为医疗诊断或紧急服务。
- 风险识别出现漏报或误报。
- 守护通知的授权含义不够清晰。
- 陪伴文本模板化，无法形成长期使用动机。
- TTS 成本、额度和浏览器策略影响一致性。
