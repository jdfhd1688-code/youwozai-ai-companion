# 有我在项目资料索引

这套资料用于证明项目采用规范驱动开发，而不只是生成前端页面。所有“已实现”结论都应能在代码、测试或演示中找到证据；没有真实数据的部分明确标为待验证。

## 产品资料

- [产品需求文档](./PRD.md)：用户、问题、范围、需求和验收标准。
- [产品与技术规格](./SPEC.md)：业务规则、状态、接口和非功能要求。
- [安全设计](./SAFETY.md)：High Risk 边界、失败处理与审计要求。
- [用户价值验证计划](./VALIDATION.md)：访谈、可用性测试和指标口径。
- [版本路线图](./ROADMAP.md)：按风险和证据排序的后续工作。

## 工程资料

- [系统架构](./ARCHITECTURE.md)：模块边界、数据流和数据模型。
- [测试策略](./TESTING.md)：自动化测试、人工验收与发布门禁。
- [SDD 工作方式](./SDD.md)：从需求到代码的可追踪流程。
- [Harness 工程](./HARNESS.md)：上下文、工具、质量门禁和恢复方式。
- [技术决策记录](./DECISIONS.md)：关键方案、理由和代价。
- [版本记录](./CHANGELOG.md)：已完成能力与验证结果。

## 投递与面试

- [根目录一页说明](../PORTFOLIO.md)：随 Demo 或简历发送。
- [演示手册](./DEMO.md)：5–8 分钟标准演示路径。
- [面试讲稿](./INTERVIEW.md)：项目叙述、难点和诚实边界。
- [作品集交付清单](./PORTFOLIO_CHECKLIST.md)：发布前需要补齐的证据。

## 推荐阅读顺序

面试官先看 `PORTFOLIO.md` 和 Demo；产品负责人看 `PRD.md`、`VALIDATION.md` 和 `SAFETY.md`；技术负责人看 `ARCHITECTURE.md`、`SPEC.md`、`TESTING.md` 和 `DECISIONS.md`。
