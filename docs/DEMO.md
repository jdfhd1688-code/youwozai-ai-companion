# 有我在标准演示手册

## 演示目标

在 5–8 分钟内证明这是一个有后端、有数据、有权限、有安全边界和自动化验证的产品，而不只是页面原型。

## 演示前检查

```bash
pnpm install
pnpm test
pnpm build
pnpm dev
```

- 打开 <http://localhost:3000>。
- 确认 Demo 数据已初始化。
- 检查 `.env.local` 未进入任何演示文件或版本控制。
- 如果 TTS Provider 无额度，提前说明将展示系统语音 fallback。

## 演示路径

### 1 产品问题 30 秒

“很多人不是没有情绪记录需求，而是不愿意先填一张表。我让用户先与小在自然聊天，再把有价值的内容整理成由用户确认的记录。”

### 2 普通聊天与记录 90 秒

发送 Low 示例，展示陪伴回复、结构化草稿、修改和保存。强调 AI 结果不会直接写入数据库。

### 3 长期价值 60 秒

进入“我的这一段路”和每周来信，说明 SQLite 中的已确认记录如何被回顾和聚合，而不是只保存聊天气泡。

### 4 守护圈与权限 90 秒

展示逐人授权矩阵。说明“需要支持”“风险等级”“情绪标签”等字段独立控制。

### 5 High Risk 90 秒

发送 High 示例，展示固定安全回复、三个主操作、待确认通知、撤销和审计。明确当前通知是站内模拟。

### 6 语音体验 60 秒

第一次点击解锁，展示自然 TTS 或系统降级；开启自动播放后发送新消息；播放中切换页面证明声音停止；展示 High Risk 更慢的 safety voice。

### 7 工程证据 60 秒

打开 `docs/SPEC.md`、`docs/TESTING.md` 和测试输出，说明需求编号、降级策略与 36 项测试。

## 常见异常

- TTS 额度不足：说明 Provider 返回失败，文字正常，语音降级；不要假装自然 TTS 已成功。
- 端口占用：关闭旧 dev 进程后重新启动。
- 数据状态混乱：使用 Demo 账号重新开始，不删除用户真实目录。
- 浏览器静音：先检查标签页和系统音量，再判断应用错误。
