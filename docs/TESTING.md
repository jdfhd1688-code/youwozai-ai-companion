# 有我在测试策略

## 质量目标

测试重点不是页面是否能打开，而是风险流程、权限边界、降级能力和音频副作用不会因迭代被破坏。

## 自动化测试

当前 `pnpm test` 包含 36 项测试，分为：

- `risk.test.ts`：基础风险分级。
- `risk-expanded.test.ts`：扩展表达和边界样本。
- `workflow.test.ts`：High Risk、守护权限和通知流程。
- `display.test.ts`：前端展示和敏感内容规则。
- `voice-playback.test.ts`：解锁、自动播放、暂停恢复、请求取消、超时、fallback 和单音轨。
- `display.test.ts` 还保护 Phase 1 四模块 IA、基础回顾说明和虚构 Demo 标识。

`pnpm verify:ui` 使用实际浏览器检查移动端六路由、桌面端“这一段路”、新用户空状态、四项一级导航、核心 GET API、console error 和失败请求。

## 发布前命令

```bash
pnpm install
pnpm test
pnpm build
pnpm dev
```

必须保存实际结果，不把“计划执行”写成“已经通过”。

## 人工验收矩阵

| 场景 | 预期结果 |
| --- | --- |
| 首次打开并开启自动播放 | 在第一次用户主动操作前不自动发声 |
| 首次点击播放或发送 | AudioContext 解锁，当前语音可播放 |
| 解锁后产生新回复 | 开启自动播放时自动播，关闭时不播 |
| 连续触发两条语音 | 新语音停止旧语音，不重叠 |
| 播放中切页 | 立即停止播放和待处理请求 |
| TTS 返回失败 | 文字保留，系统语音可用时降级 |
| High Risk 回复 | 使用 safety voice 和更慢语速 |
| 无守护权限 | 不产生越权通知 |
| 通知撤销 | 状态和时间戳正确，不能显示为已发送 |
| 注销账号 | 用户关联数据按设计删除 |

## 尚缺测试

- Playwright 端到端测试及 CI 浏览器矩阵。
- 真实 OpenAI LLM/TTS 的受控集成测试。
- API 鉴权、越权访问和限流安全测试。
- SQLite 迁移、备份和恢复测试。
- 屏幕阅读器、键盘操作和颜色对比度测试。
- Provider 延迟、并发和成本压测。

## 缺陷分级

- P0：High Risk 流程失效、越权分享、数据泄露或无法登录。
- P1：记录丢失、通知状态错误、声音重叠或主要流程阻断。
- P2：降级提示、视觉同步、布局或非核心交互问题。
- P3：文案、轻微样式和不影响任务完成的问题。

P0、P1 未关闭不得发布；P2 必须进入已知问题并指定处理版本。
