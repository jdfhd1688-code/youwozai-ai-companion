# 有我在 AI 开发 Harness

## Harness 目标

让不同 AI 编码工具在有限上下文中仍能理解产品边界、遵守安全约束、使用一致的验证命令，并能在中断后恢复工作。

## 上下文层级

按以下顺序读取，避免一次加载整个仓库：

1. `README.md`：运行方式和当前能力。
2. `PORTFOLIO.md`：产品定位和真实边界。
3. `docs/PRD.md`：产品范围。
4. `docs/SPEC.md`：需求编号和验收标准。
5. 与任务相关的领域文档，如 `SAFETY.md` 或 `TESTING.md`。
6. 只读取与目标相关的源文件和测试。

## 工具编排

- 文件定位优先使用 `rg` 和 `rg --files`。
- 本地修改使用最小补丁，保留用户已有更改。
- 开发后运行与变更最接近的测试，再运行完整测试和构建。
- UI、副作用、浏览器策略相关变更必须进行浏览器人工验证。
- 外部 Provider 测试不得输出密钥、完整用户文本或音频内容。
- 删除、覆盖数据或修改真实外部系统前必须确认目标和权限。

## 强制质量门禁

| 变更类型 | 最低验证 |
| --- | --- |
| 文案或样式 | 相关页面人工检查 + build |
| 业务规则 | 单元测试 + 完整 test + build |
| 数据库 | 数据访问测试 + 迁移检查 + 回滚说明 |
| High Risk | 风险样本 + 权限矩阵 + 人工安全流程 |
| 语音 | 播放并发测试 + 浏览器解锁/自动播/切页测试 |
| Provider | 成功、超时、额度不足和无配置四种路径 |

```text

```

## 反模式

- 未读取 Spec 就直接修改代码。
- 把外部 API 不可用误判为前端播放错误。
- 用 UI 隐藏失败，而不保留可观察状态。
- 为赶进度删除安全流程、权限校验或既有测试。
- 把本地模拟通知写成“真实通知已上线”。
- 把计划指标写成真实用户结果。
