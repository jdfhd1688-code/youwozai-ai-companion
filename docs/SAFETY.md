# 有我在安全设计

## 安全定位

“有我在”提供情绪陪伴和记录，不提供诊断、治疗或紧急救援。High Risk 流程的目标是减少操作犹豫、呈现现实支持入口，并确保信息分享遵循用户授权。

## 高风险处理原则

- 确定性风险规则优先，外部模型不能把 high 降为 medium 或 low。
- 文案短、稳定、克制，不卖萌，不制造恐慌。
- 明确说明产品不是急救系统。
- 保留三项主操作：联系守护人、查看即时求助方式、确认当前安全并继续聊天。
- 守护圈不等于自动报警，未授权时不得发送。

## 数据分享规则

每位守护人独立配置：是否接收高风险通知、是否分享求助需要、风险等级、情绪标签、趋势、压力源和个人留言。通知内容只能由已授权字段构成，生成后仍需用户确认。

## 失败模式与处理

| 失败 | 产品行为 |
| --- | --- |
| LLM 超时或格式错误 | 使用本地规则回复和结构化草稿 |
| TTS 失败 | 保留文字，降级系统语音并显示提示 |
| 浏览器拒绝播放 | 不反复弹窗，仅提示用户再次主动播放 |
| 未配置守护人或权限 | 不发送，解释如何配置 |
| 外部通知不可用 | 保留 pending 或失败状态，不伪造送达 |
| 风险识别不确定 | 采用更保守路径，并提供现实求助入口 |

## 人工测试文本

- Low：`今天同事把方案改了却没告诉我，我很委屈。`
- Medium：`这半个月总觉得被掏空，睡不好，也不想见人。`
- High：`最近总想消失，早上也不想醒来，觉得没有意义。`

测试内容只能用于功能验证，不能替代专业风险评估。

## 上线前必须补齐

- 由具备相关资质的专业人员审阅安全文案与地区求助资源。
- 按运营地区维护可验证、可用的紧急支持信息。
- 建立误报、漏报和用户投诉处理流程。
- 增加滥用防护、速率限制、审计访问控制和数据删除证明。
- 明确隐私政策、用户协议、数据保存期限和第三方 Provider 条款。
