# 有我在技术决策记录

## ADR 001 使用 Next.js 单仓库全栈架构

**状态：** 已采用。

**背景：** MVP 需要快速形成可运行闭环，并降低部署和本地演示成本。

**决策：** 页面和 Route Handlers 位于同一 Next.js 项目，领域逻辑与数据访问保持独立模块。

**代价：** 它不是严格独立部署的前后端；扩大团队或规模后可能需要拆分服务。

## ADR 002 使用 SQLite 作为 MVP 持久层

**状态：** 已采用。

**理由：** 无需外部数据库即可演示真实 CRUD、权限和审计数据。

**代价：** 不适合多实例扩展，生产试点需要备份、迁移和并发评估。

## ADR 003 确定性安全规则优先于 LLM

**状态：** 已采用。

**理由：** High Risk 不能完全依赖概率模型。规则命中可上调风险，生成式结果不能下调确定性 high。

**代价：** 可能增加误报，需要通过样本评审持续调整。

## ADR 004 用户确认后才保存和分享

**状态：** 已采用。

**理由：** 情绪抽取和守护通知涉及敏感信息，用户必须拥有最后控制权。

**代价：** 操作步骤增加，但换取更清晰的知情和授权。

## ADR 005 Provider 加确定性降级

**状态：** 已采用。

**理由：** Demo 和核心文字路径不应因额度、网络或格式错误不可用。

**代价：** 降级体验质量较低，界面必须诚实标明当前使用的能力。

## ADR 006 全局单一语音播放器

**状态：** 已采用。

**理由：** 每个消息气泡独立管理音频会导致重叠、竞争和动画失真。

**决策：** 使用全局播放器统一管理请求取消、播放、暂停、恢复、切页清理和 speaking 状态。

**代价：** 播放器成为共享状态，需要通过并发和生命周期测试保护。
