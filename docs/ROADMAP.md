# 有我在版本路线图

## 排序原则

先补证据和安全，再补真实外部能力，最后才增加新功能。没有用户验证支持时，不扩展社区、商城、小游戏等范围。

## P0 作品集可投递

- 初始化 Git 仓库，建立可读提交历史并推送 GitHub。
- 部署一个可访问的 Beta 地址。
- 轮换已暴露的 API Key，并配置有额度的服务端密钥。
- 完成 5–10 名用户的第一轮可用性测试。
- 补充 4–6 张关键路径截图和一段 2–3 分钟演示视频。

## P1 真实试点准备

- Playwright 端到端测试和 CI。
- 错误码、Provider 延迟、fallback 比例等匿名化监控。
- API 限流、滥用防护、生产 Cookie 和安全头。
- SQLite 备份恢复方案，或迁移 PostgreSQL。
- 由专业人员审阅 High Risk 文案和地区支持资源。
- 明确隐私政策、用户协议和数据保留周期。

## P2 价值增强

- 根据访谈调整首次聊天、情绪草稿和每周来信。
- 接入真实通知 Provider，但继续保留确认和权限审计。
- 接入语音输入并明确录音权限和数据处理方式。
- 为来信和趋势增加可解释来源，而不是生成空泛总结。

## 暂不投入

- 社区、陌生人匹配、排行榜和商城。
- 实时视频或电话外呼。
- 医疗诊断、完整心理测评和咨询师交易。
- 复杂唇形同步或高成本 3D 角色。
